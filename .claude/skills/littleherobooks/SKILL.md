# Little Hero Books (native Anvil Forms)

**What it is:** personalised picture books (hero studio, 12 tales, reader, PDF, family links; README.md lists every
feature). Since 2026-11-02 the interface is native Anvil Forms: one Python Form per page with an HTML template, a layout
Form for the frame, custom components, RepeatingPanels with item templates. The drawing engines (cartoon people, story
pictures, reader, PDF writer) stay JavaScript and are called from Python. The product, look and story/avatar recipes are

## Workflow

1. Edit. Templates and Python side by side (`Pages/Studio/form_template.html` + `__init__.py`).
2. `python tools/check.py` (no -I) -> ALL CHECKS PASSED. Needs the Anvil CLI (`npm install -g @anvil-works/anvil-cli`,
   or ANVIL_CLI=path). It type-checks Python against Anvil's stubs: it catches real bugs (None subscripts, wrong
   component properties, missing imports).
3. `python -I tools/ui_test.py` (Docker Desktop running) -> ALL UI TESTS PASSED. Runs the folder as-is in
   anvilworks/anvil-app-server:1.18.0 on http://localhost:3031 (container lhb-dev, volume lhb-data). Client changes
   show on reload; server changes need `--restart`. `--shots DIR` = every page, desktop + true 390 px phone,
   light + dark, guest + signed in (tools/ui/seed.js makes an account, a hero and a book). Read the PNGs.
4. `git pull --ff-only` first (Anvil commits IDE edits). Commit only your files as arkulinskis with the Co-Authored-By
   line, `git push origin master`. Risky change: push a branch and ask the user for a debug link of it.

## Patterns (how this branch does things)

- **Page** = `<anvil-form layout="Little_Hero_Books.Layouts.Shell" prop:active="home"><anvil-block slot="content">...`
  + a class taking `args=()` (the URL parts). Add it to `router.PAGES` and `router._form`.
- **Anvil keeps the layout instance between pages** (open_form only swaps the slot when the layout matches). So
  anything in the Shell that depends on who is signed in is redrawn in `Shell.refresh()` (router calls it after
  every page), never only in `__init__`.
- **Navigation** = plain `<a href="#library">` (real links). Code: `router.go("book", id)`; `router.replace` changes
  the address without reopening.
- **Actions** = Anvil `Button` with roles `["btn", "btn-primary", "ic-wand"]` and `@handle("name", "click")`.
  Variants: btn-sm/lg/sun/ghost/danger/icon/block/on. Icons: role `ic-<name>` or `<i class="ic ic-<name>">`.
- **Text that changes** = `Label` (roles for the look: page-title, bk-title, fine-print, badge ...). Static copy is
  plain HTML in the template.
- **Plain HTML that changes** = `anvil:name="x"` then `self.x.visible`, `self.x.classes["on"] = ...`,
  `self.x.style[...]`; attributes with `state.set_attr(self.x, "href", ...)` (HtmlComponent.attrs isn't in the
  open-source runtime yet). Native clicks: `anvil:on-dom:click="self.x_click"` with `def x_click(self, event)`.
- **Lists** = RepeatingPanel + an `Items.*` form; grid CSS goes on the role's items container
  (`.anvil-role-lb-grid > div`). Item -> page messages: `self.parent.raise_event("x-make", story=...)` and the page
  `panel.add_event_handler("x-make", ...)`. Role `contents` makes a panel's items join the surrounding grid.
- **Pictures** = Components.Avatar / Cover / Scene (properties redraw). Need the engine directly? Add a function in
  lh.py.
- **Dialogs** = a Form in Dialogs/ shown with `alert(Form(...), buttons=[], role="lh-dialog")`; it closes itself with
  `self.raise_event("x-close-alert", value=...)` and alert returns the value.
- **Server calls** = `state.call("fn", ...)`: expected problems come back as `{"ok": False, "error"}` -> toast + None.
  Pages that show a friendly state instead (private book, broken family link) call anvil.server.call and check ok.

## Gotchas found building it (Nov 2026)

- App Server 1.18 (local) lags hosted Anvil: no `HtmlComponent.attrs`, `Notification(role=)` raises TypeError
  (state.toast falls back to `style=`), notifications are `.anvil-alert[data-notify]` instead of `.anvil-notification`,
  and every named element/component is wrapped in `<anvil-dropzone>` (app.css sets `display: contents`). Style both.
- Headless Chrome + Anvil's service worker: reusing a profile gives ERR_FAILED; drive.mjs bypasses the worker.
- Headless windows can't be narrower than ~500 px: phone runs use device emulation (MOBILE=390,844 in drive.mjs).
- `PasswordNotAcceptable` isn't always an `AuthenticationFailed` subclass: auth.py catches every expected class.
- `require_secure_passwords` rejects leaked passwords; tests use random ones.
- Heredocs with JS/HTML in the Bash tool break on quotes: write files with the Write tool.
