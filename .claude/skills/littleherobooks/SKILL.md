# Little Hero Books (native Anvil Forms)

**What it is:** personalised picture books (hero studio, 12 tales, reader, PDF, family links; README.md lists every
feature). Since 2026-11-02 the interface is native Anvil Forms: one Python Form per page with an HTML template, a layout
Form for the frame, custom components, RepeatingPanels with item templates. The drawing engines (cartoon people, story
pictures, reader, PDF writer) stay JavaScript and are called from Python. The product, look and story/avatar recipes are
in the old guide, C:\Users\arkvi\Documents\CLAUDE\little-hero-books\.claude\skills\littleherobooks\SKILL.md (the engines didn't change: _avatar.html = theme/assets/lh-avatar.js,
_scenes.html = lh-scenes.js, _book.html = lh-book.js).

**Where it lives:**
- Folder `C:\Users\arkvi\Documents\CLAUDE\little-hero-books-components\` = a git clone of
  github.com/arkulinskis/little-hero-books, branch **master** (live at https://little-hero-books.anvil.app).
  **"git" layout**: the folder *is* the Anvil app (no sync step). Edit, commit, `git push origin master`.
- The old JavaScript source folder `little-hero-books` is retired (its deploy.py refuses to run).

## Workflow

1. Edit. Templates and Python side by side (`Pages/Studio/form_template.html` + `__init__.py`).
2. `python tools/check.py` (no -I) -> ALL CHECKS PASSED. Needs the Anvil CLI (`npm install -g @anvil-works/anvil-cli`,
   or ANVIL_CLI=path). It type-checks Python against Anvil's stubs: it catches real bugs (None subscripts, wrong
   component properties, missing imports).
3. `python -I tools/ui_test.py` (Docker Desktop running) -> ALL UI TESTS PASSED. Copies the app into
   anvilworks/anvil-app-server:1.18.0 on http://localhost:3031 (container lhb-dev, volumes lhb-app + lhb-data,
   `--auto-migrate`). Client changes apply on the next run; server changes need `--restart`. `--shots DIR` = every page, desktop + true 390 px phone,
   light + dark, guest + signed in (tools/ui/seed.js makes an account, a hero and a book). Read the PNGs.
4. `git pull --ff-only` first (Anvil commits IDE edits). Commit only your files as arkulinskis with the Co-Authored-By
   line, `git push origin master`. Risky change: push a branch and ask the user for a debug link of it.

## Patterns (how this branch does things)

- **Page** = `<anvil-form layout="Little_Hero_Books.Layouts.Shell" prop:active="home"><anvil-block slot="content">...`
  + a class taking `args=()` (the URL parts). Add it to `router.PAGES` and `router._form`.
- **Anvil keeps the layout instance between pages** (open_form only swaps the slot when the layout matches). So
  anything in the Shell that depends on who is signed in is redrawn in `Shell.refresh()` (router calls it after
  every page), never only in `__init__`.
- **Navigation** = plain `<a href="#library">` (real links). Code: `router.go("book", id)`; `router.replace` changes
  the address without reopening.
- **Actions** = Anvil `Button` with roles `["btn", "btn-primary", "ic-wand"]` and `@handle("name", "click")`.
  Variants: btn-sm/lg/sun/ghost/danger/icon/block/on. Icons: role `ic-<name>` or `<i class="ic ic-<name>">`.
- **Text that changes** = `Label` (roles for the look: page-title, bk-title, fine-print, badge ...). Static copy is
  plain HTML in the template.
- **Plain HTML that changes** = `anvil:name="x"` then `self.x.visible`, `self.x.classes["on"] = ...`,
  `self.x.style[...]`; attributes with `state.set_attr(self.x, "href", ...)` (HtmlComponent.attrs isn't in the
  open-source runtime yet). Native clicks: `anvil:on-dom:click="self.x_click"` with `def x_click(self, event)`.
- **Lists** = RepeatingPanel + an `Items.*` form; grid CSS goes on the role's items container
  (`.anvil-role-lb-grid > div`). Item -> page messages: `self.parent.raise_event("x-make", story=...)` and the page
  `panel.add_event_handler("x-make", ...)`. Role `contents` makes a panel's items join the surrounding grid.
- **Pictures** = Components.Avatar / Cover / Scene (properties redraw). Need the engine directly? Add a function in
  lh.py.
- **Dialogs** = a Form in Dialogs/ shown with `alert(Form(...), buttons=[], role="lh-dialog")`; it closes itself with
  `self.raise_event("x-close-alert", value=...)` and alert returns the value.
- **Server calls** = `state.call("fn", ...)`: expected problems come back as `{"ok": False, "error"}` -> toast + None.
  Pages that show a friendly state instead (private book, broken family link) call anvil.server.call and check ok.

## Record my voice (Prepsto idea, 2026-11-05)

- **Table `voice_pages`**: book (link), page (0 cover, 1 dedication, 2-10 story, 11 The End), audio (media), seconds,
  key (random, 24 chars), created. One row per recorded page; Redo replaces the row (new key).
- **Server (Voice.py)**: `save_voice(book_id, page, media, seconds)` (owner only, audio/* or video/webm, 200 B-4 MB,
  stored without the codecs part of the type), `delete_voice(book_id, page=None)` (None = all). `get_book` (owner) and
  `get_shared_book` add `voice: {"<page>": {key, seconds}}`. `delete_book`, `delete_hero` remove recordings;
  `share_book` (on or off) calls `Voice.new_keys`, so old audio addresses die with the old link.
- **Audio endpoint** `/_/api/voice/:key`: byte ranges (206, Safari/iPhone need them), `Cache-Control: private,
  no-cache` + ETag = key (304s), so a deleted recording stops playing at once (with max-age the browser kept playing a
  deleted page from its cache: the flow test caught it).
- **Engine (lh-book.js)**: the record panel `[data-rd-rec]` above the page (like the crayons), states empty / starting /
  recording / saving / saved / error, buttons `[data-rec=start|stop|play|redo|delete|next|clear]`. The mic stream is
  kept while record mode is on (one permission prompt) and released when it closes. Turning the page while recording
  stops and saves it. A fresh recording plays from a blob URL; after a reload from the server. Pages without a
  recording use speech synthesis. Python callbacks return JSON strings (`onVoiceSave`, `onVoiceDelete`).
- **Tests**: server tests cover every rule above; flow.js records with Chrome's fake microphone (drive.mjs passes
  `--use-fake-device-for-media-stream` etc.; `FAKE_AUDIO=<wav>` for real speech), plays back, redoes, checks the 206,
  reloads, plays via Read to me, checks the family link, deletes one page and all. The reader's controller is
  `document.querySelector('.rd').parentNode.lhReader` (voice(), audio(), playing(), at()).
- Not verified here: a real iPhone/Safari recording and playback (MediaRecorder MP4/AAC is expected there).

## Paint this book (2026-11-08)

- **What:** every picture of a book repainted by Image Enhancer (the user's own service: github.com/arkulinskis/
  image-enhancer, folder `image-enhancer`; its API guide is its README and Connect page). `server_code/
  enhancer_client.py` is a copy of that repo's `clients/enhancer_client.py` (keep them the same); `Painting.py` is the
  only module that uses it.
- **Table `paintings`**: book, page (same numbers as voice_pages: 0 cover, 1 dedication, 2.. story, last The End),
  style, source (the PNG sent), picture (the result), picture_style, key (random, serves /painting/<key>), job_id,
  status (sending / queued / working / done / failed), error, eta, attempts, created, updated, checked.
  One row per page; repainting reuses the row and keeps `picture` until the new one is done.
- **Server:** `paint_info` (styles, ready, the studio's queue, state), `paint_page(book, page, style, png)` (owner,
  PNG/JPEG/WebP 500 B-8 MB, 150 new pages a day per person, cancels the page's old queued job), `paint_status`
  (checks open jobs at most every 10 s: one `GET /jobs?status=open` when more than 3, then single calls; "sending"
  rows are sent again; a 404 job is sent again), `paint_remove`, `admin_painting*`. Webhook `/paint-done` (HMAC with
  `image_enhancer_webhook_secret`; Image Enhancer only calls https, so not locally). Endpoint `/painting/:key`
  (private, no-cache, ETag = key, like voice). `get_book` adds `paint` + `paint_state` (owner), `get_shared_book`
  adds `paint`; `share_book` gives new keys; `delete_book` / `delete_hero` delete rows (queued jobs cancelled).
  Each page is sent with fidelity "strict", size "source", format jpeg and a prompt asking to keep faces/clothes and
  add no words (`Painting.PROMPT`). Six kid-friendly styles of Image Enhancer's ten (`Painting.STYLES`).
- **Style samples (2026-11-09):** the Paint dialog shows the same drawing (Juniper on the Three Bears cover) painted
  in each style: a big preview of the chosen one with the drawing in the corner, and a card per style
  (`theme/assets/paint-<style>.jpg`, `paint-drawing.jpg`, `Items/PaintStyle.preview_url`). They were painted by the
  real model with the exact book instructions. **After changing `PROMPT`, `STYLE_EXTRA`, `hero_words` or a style in
  Image Enhancer, run `tools/paint_previews.py` on the studio PC** (draws the page with the live engine, paints it
  through ComfyUI with the worker's engine, saves the JPEGs) and look at them before committing.
- **Instructions the model gets** = Image Enhancer's style words + its "strict" sentence + `prompt_for(book, style)`:
  `hero_words(look)` ("The child has fair skin, ginger curly hair, freckles and round glasses."), `PROMPT`, and
  `STYLE_EXTRA[style]`. Lessons from the first previews: without the hero in words, Clay darkened a fair child's skin
  and dropped the glasses; "Fairy-tale painting" turned the meadow into a forest with a creature; saying "a page of a
  picture book" made the model paint an open book over the characters; "add no creatures" made it drop the bears.
  Keep the total under 600 characters (Image Enhancer's limit; a server test checks the worst case).
- **Saved styles (2026-11-09):** table `saved_paintings` (book, page, style, look, picture, created) keeps every
  finished picture per style (`_save` in `_apply`; older paintings are backfilled by `remember`). `look` =
  `look_key(book)`, a fingerprint of the story + hero look; rows of another look don't match and are deleted when the
  Paint dialog opens (`saved_styles(prune=True)`). `paint_saved(book, style)` puts the saved pictures on the book at
  once (new keys, no job) and returns the pages still missing; the dialog then sends only those. Cards show "Saved" /
  "7 of 12 saved"; the main button becomes "Switch to <style>", "Paint fresh" ignores the saved ones, the current style
  offers "Paint it fresh", "Delete saved styles" = `paint_forget`. "Back to the drawings" (`paint_remove`) keeps the
  saved styles; removing the book or hero deletes them. `paintings.look` remembers the look a page was sent with.
- **The drawing is the truth (2026-11-09, the user's rule):** every pass starts from the page's own vector drawing.
  `paint_page` accepts only a PNG at the drawing's size (`SOURCE_SIZES`: 1216x851 scenes, 1024x1024 dedication/End,
  `png_size`), so a painted JPEG or a style sample (800x560) can never become the base; resends after a lost job use
  the stored `source`. The ComfyUI workflow loads exactly one image (that drawing) as the reference
  (`ReferenceLatent`); the samples in theme/assets are display-only. `tools/testing/paint_e2e.py` checks it: every
  Image Enhancer job of a page got byte-identical PNG bytes ("ok truth: ...").
- **The hero in words:** `hero_words(look, pronoun)` = skin first in its own sentence ("His skin is dark brown, as dark
  as in the drawing."), then girl/boy/child, age, eyes, hair, freckles, rosy cheeks, outfit with colour, glasses and
  hats only when chosen. NEVER name a feature in the general rules (`PROMPT`, `STYLE_EXTRA`) that a child may not
  have: "keep ... glasses" gave every child (and Papa Bear) glasses in the 2026-11-09 Kofi test.
- **Seeds:** `seed_for(book, page, style)` = the same seed every time (same drawing + words + seed = same picture);
  "Paint fresh" sends `fresh=True` (column `paintings.fresh`) and no seed.
- **Skin check + Repaint this page (2026-11-09, after a fair child came out dark):** when a picture arrives the
  owner's book page runs `lh.skin_check` (`LH.skinCheck`: draws the page twice, once with the hero's skin in marker
  green, so the differing pixels are exactly the hero's skin; compares their CIE L* in the painting vs the drawing,
  minus the whole picture's change, trimmed means) and sends it to `paint_verdict`. |relative| > `SKIN_TOLERANCE`
  (25) -> repainted from the stored vector drawing with a new seed, up to `MAX_AUTO_RETRIES` (2), then
  `verified=False` (flag: warning above the page + strip). Calibration: correct paintings +-16 (style lighting
  included), flips 40-55; browser test in flow.js (same 0, fair->dark -50, dark->fair +50, near shade -5). Columns
  `paintings.verified/auto_retries/skin_check`; `paint_for` entries carry done/checked/flag. "Repaint this page" (Book
  page toolbar, the page open in the reader) = `paint_page(..., fresh=True)` for that page only.
- **Address:** Admin → Painting (app_settings `enhancer_api`) > App Secret `image_enhancer_url` > enhancer_client.API.
- **Client:** `Dialogs/Paint` (styles via `Items/PaintStyle`, the queue line, sends page by page with
  `lh.paint_picture` -> `anvil.js.to_media` -> `paint_page`), the Book page's strip + `paint_timer` (15 s while
  painting) + `reader.set_paint()`, `books.as_book` adds `paint` and `paintBase` (/_/api/painting/), the Pdf dialog's
  "Use the painted pictures" (`opts.painted`).
- **Engine (lh-book.js):** `LH.paintIndex/paintSrc/hasPaint`, `LH.pageHtml(..., {painted})` swaps the SVG for
  `<img class="rd-painted">` (never in Colour me in), the reader's `[data-rd=paint]` switch (`UI.store` "painted"),
  `setPaint(map)` redraws the open page without a page turn, `preload()` loads the next painted picture,
  `LH.paintPicture(book, idx)` = the PNG sent (scenes 1216x851 without grain, dedication 1024² on yellow, End figure
  on a 1024² warm-paper square), the PDF's `pictureOf()` (painted picture, else the drawing).
- **Tests:** server tests fake Image Enhancer in `anvil.http.REPLIES`. `tools/testing/paint_e2e.py` (run with a
  Python that has anvil-uplink + pillow) starts Image Enhancer's local server and its real worker with the test
  filters, recreates this app's server with `LHB_SECRETS` (`--secret` flags) and runs `tools/ui/paint.js` at desktop
  and phone width: paint, watch pages arrive, every page kind, the switch, Colour me in, PDF dialog, reload, back to
  the drawings, paint again. Without secrets, flow.js checks the dialog says the studio isn't open.
- Item templates: put `classes`/attributes on `self` (the root element), not on an `anvil:name` at the root (the
  validator doesn't know it, and the class didn't apply).

## Gotchas found building it (Nov 2026)

- **A remounted reader must drop its click listener.** The Reader component remounts into the same DOM node (e.g. after
  the dedication changes); before 2026-11-05 the old instance's `click` listener stayed, so every later click ran the
  old reader too (old onPage/onFinish, and a crash on Play). `destroy()` now removes it.
- ui_test.py copies the app into the Docker volume `lhb-app` and runs `--auto-migrate` (since 2026-11-05: new tables
  apply locally; `remembered_logins` is listed in anvil.yaml's users table, so no `--ignore-invalid-schema`).

- App Server 1.18 (local) lags hosted Anvil: no `HtmlComponent.attrs`, `Notification(role=)` raises TypeError
  (state.toast falls back to `style=`), notifications are `.anvil-alert[data-notify]` instead of `.anvil-notification`,
  and every named element/component is wrapped in `<anvil-dropzone>` (app.css sets `display: contents`). Style both.
- Headless Chrome + Anvil's service worker: reusing a profile gives ERR_FAILED; drive.mjs bypasses the worker.
- Headless windows can't be narrower than ~500 px: phone runs use device emulation (MOBILE=390,844 in drive.mjs).
- `PasswordNotAcceptable` isn't always an `AuthenticationFailed` subclass: auth.py catches every expected class.
- `require_secure_passwords` rejects leaked passwords; tests use random ones.
- Heredocs with JS/HTML in the Bash tool break on quotes: write files with the Write tool.
